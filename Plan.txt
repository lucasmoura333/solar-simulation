Wayfinder - Protótipo PVSOL-like para Estudos e Integração Futura
Objetivo deste documento: servir como um roteiro (roadmap) e guia de decisões para a construção de um protótipo funcional rodando no navegador, que simule o posicionamento de módulos solares em telhados, com cálculos básicos de sombreamento e produção de energia. Este protótipo será utilizado como material de estudo e, posteriormente, integrado a um projeto de maior porte.

1. Visão Geral do Protótipo (MVP Técnico)
1.1. O que vamos construir?
Uma aplicação web (React + TypeScript) com uma cena 3D interativa (Three.js).

O usuário poderá:

Desenhar um telhado (ou usar uma forma geométrica simples).
Posicionar módulos solares sobre o telhado, arrastando-os ou clicando.
Configurar parâmetros de cada módulo (potência, eficiência) e conectá-los a "MPPTs" (nodes).
Simular a trajetória do sol e ver sombras projetadas em tempo real.
Calcular a produção de energia com base nos dados inseridos e na irradiação estimada.
1.2. Escopo mínimo para ser "minimamente visível"
Uma única edificação com telhado inclinado (duas águas ou simples).

Capacidade de adicionar, mover e excluir módulos solares sobre o telhado.

Exibição de dados dos módulos (potência, tensão) via painel lateral.

Simulação de sombra usando uma fonte de luz direcional que o usuário pode movimentar (ou que se mova automaticamente ao longo do tempo).

Cálculo de produção total (kWh) simplificado (apenas usando um valor fixo de irradiação, sem dados climáticos reais).

1.3. Entregáveis do protótipo
Código-fonte organizado em um repositório Git.

Uma página web que pode ser executada localmente (npm start).

Documentação básica (este arquivo e comentários no código).

Um pequeno relatório/estudo sobre decisões de performance e arquitetura.

2. Stack Tecnológica (Escolhas Fundamentadas)

Gerenciamento de Estado	Zustand	Leve, simples e eficiente, evita re-renderizações desnecessárias.

Gráficos/Relatórios	Recharts	Integração simples com React, boas opções de visualização.

□ Armazenar esses dados no moduleStore.

□ Acumular a produção diária/anual e exibir no painel de estatísticas.
□ Usar Recharts para plotar um gráfico de produção ao longo do dia.
5. Considerações de Performance (Crucial)
InstancedMesh: Todos os módulos solares devem ser renderizados como uma única instância. Use InstancedMesh para painéis idênticos.

Culling: Objetos fora do campo de visão da câmera não devem ser processados (Three.js já faz isso por padrão com frustumCulled).

Geometria simples: Telhados devem ter poucos polígonos (não usar malhas com detalhes desnecessários).

Simshady na GPU: Configurar corretamente para usar o WebGL2 e evitar transferências pesadas de dados entre CPU e GPU.

Debounce no slider solar: Não atualizar a simulação a cada frame se o usuário estiver arrastando o slider. Faça updates apenas ao soltar.

6. Integração com um Projeto Futuro (Escalabilidade)
Arquitetura modular: Cada fase implementada como um módulo independente (ex: @meuprojeto/phase1, etc.) para facilitar a extração.

API de comunicação: Em vez de armazenar dados apenas no Zustand, crie um serviço (ex: SimulationService) que pode ser substituído por chamadas a uma API REST no futuro.

Exportação de dados: O protótipo deve exportar todo o estado (posições, configurações) em JSON, permitindo que seja lido pelo sistema maior.

Web Workers: Separe os cálculos pesados (ex: simulação anual) em um worker para não bloquear a UI.

Design System: Use um sistema de design (ex: Chakra ou Tailwind com componentes customizados) para manter consistência visual.
